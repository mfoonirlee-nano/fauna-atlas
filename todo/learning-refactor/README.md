## 工作状态

同一档案可以同时具有多个状态。所有档案初始待人工审核，负责人和审核时间均留空。

| 状态 | 含义 |
| --- | --- |
| pending-editorial-review | 待阅读原文、整理儿童表达并核对重复和难词 |
| pending-source-review | 待核对名称、分类、逐条事实与来源及其时效 |
| pending-image-review | 待核对现有图片的生物学准确性和教学用途 |
| pending-research | 基础字段缺项或主题检索无候选，优先核对原文并补资料 |
| pending-media | 缺公开封面、图片文件缺失或已记录素材返修 |

`candidate-found` 只表示找到候选段落，`no-candidate` 只表示当前检索规则没有找到候选。`not-marked-extinct` 表示原记录未标记 EX 或 EW，不是对其现存情况的新判断。

暂不提供自动“可发布”状态。人工审核必须记录具体问题、来源、修订、负责人和日期；确认后再进入样板与迁移阶段。

## 复核顺序

1. 先处理评估状态冲突、灭绝动物当前地图点、公开素材缺失等明确结构问题；清单保留对应检测规则。
2. 对 33 份评估待核实档案和 2 份素材返修档案查证现有资料。
3. 从不同类群和现生、灭绝档案中选取样板，结合候选路径阅读原文，确认实际缺口。
4. 优先补齐身体结构、觅食、成长和生态关系，并据样板修订检索规则及内容标准。
5. 审核现有素材是否可复用，确认具体新增需求后另行安排制作。

## 生成与验证

```bash
npm run audit:learning
npm run audit:learning -- --check
npm run test:learning-audit
```

工具编译并读取正式动物目录，使用公开 `media` 检查文件，不把 `pendingMedia` 算入公开配图。生成结果写入本目录，不进入前台运行时。统计会随实际目录变化更新，文档中的本轮发现是 2026-11-10 的初始快照。

四份生成文件会被覆盖，人工审核记录应另建文件保存，并按稳定 ID 关联，不能直接在生成文件里维护。`inventory.json` 中的来源提交和 dirty 标记只针对生成时的目录数据状态；`--check` 忽略提交哈希变化，但仍比较扫描结果。新增源数据后应重新生成并核对差异。

测试覆盖 EX、EW、NE、UNVERIFIED 的区别、历史评估冲突、灭绝地图点、撤回素材隔离、文件缺失、重复 ID，以及生成清单对全量目录和素材候选的覆盖。
